# 歌帳（うたちょう）

カラオケの持ち歌・点数を管理するモバイルアプリです。歌った曲を登録し、採点結果を記録して、点数の推移をグラフで振り返ることができます。

- **プラットフォーム**: Android（Google Play でクローズドテスト中）。iOS は後続フェーズで対応予定
- **技術**: React Native 0.86 + Expo (SDK 57) / TypeScript（strict）
- **データ**: すべて端末内（SQLite）に保存。個人を特定する情報は収集しません

---

## なぜ作ったか

みなさんは、カラオケで歌える曲をどうやって覚えていますか？

多くの人は、頭のなかで記憶しているか、Spotify や YouTube Music、YouTube を見ながら思い出していると思います。歌える曲をちゃんと整理している人でも、たいていはメモ帳アプリに書き留めているくらいではないでしょうか。

でも、カラオケにそんなに頻繁に行く人って、実は少ないですよね。そして久しぶりに行ったとき、自分がどんな曲を歌えたのかをすぐに思い出せる人は、なかなかいません。メモ帳に書いてあったとしても、曲名だけ見てもピンとこないし、箇条書きのメモでは「自分がその曲にどんな思い入れがあって、どのくらい上手く歌えたのか」まではわからないんです。

そのモヤモヤを解決したくて、このアプリを作りました。

歌帳なら、アルバムの画像が表示されるので「あ、この曲か」とすぐに思い出せます。曲の検索・並び替え・タグ付けで持ち歌を整理しやすく、カラオケに行く前に「今日はこれを歌おう」とあらかじめ決めておくこともできます。

さらに、カラオケの点数を記録しておけば、頻繁に行く人も、自分がどのくらい上手くなっているか——あるいは逆に、どのくらい下手になってしまっているか——を振り返ることができます。

「久しぶりでも、頻繁に行く人でも、自分の持ち歌を思い出せて、管理できて、上達も振り返れる」。そんなカラオケのための持ち歌帳です。

## 主な機能

- **持ち歌の管理** — 曲の登録・編集・削除、タブ（カテゴリ）による多対多の分類、キー（音域）設定、メモ
- **曲検索** — iTunes Search API で「曲名 / アーティスト / キーワード」から検索し、曲名・アーティスト・アルバムアートをまとめて取り込み。見つからなければ手入力も可能
- **点数の記録** — テンキーUIでの手入力、記録日の変更、履歴の編集・削除
- **DAM / JOYSOUND の完全分離** — 最高点・グラフ・集計・自己ベストを機種別に管理。記録時にその日の機種を切り替え可能（当日限りで記憶）
- **点数推移グラフ** — 曲詳細で選択機種の折れ線グラフを表示
- **並び替え・検索** — 持ち歌リストを登録日 / 最高スコア / 記録回数 / 曲名 / アーティスト などで並び替え。ひらがな・カタカナ・全角半角・大文字小文字を区別しないローカル検索（任意の「読み」入力にも対応）
- **セットリスト・ランダム選曲** — 当日歌う曲をまとめる「今日」タブ、範囲を選んでランダムに1曲を選ぶ機能
- **バックアップ** — 全データを JSON で書き出し／読み込み（復元）
- **アプリ内ヘルプ** — 使い方・FAQ・トラブルシューティング

## 技術スタック

| 役割 | 採用 |
|---|---|
| フレームワーク | React Native 0.86 + Expo (SDK 57) |
| 画面遷移 | expo-router（ファイルベースルーティング） |
| ローカルDB | expo-sqlite |
| グラフ | react-native-gifted-charts |
| 曲情報補完 | iTunes Search API（無料・申請不要） |
| ファイル共有 | expo-sharing + expo-file-system |
| ビルド / 提出 | EAS Build / EAS Submit |
| 言語 | TypeScript（strict mode） |

## セットアップ

> Windows / macOS どちらでも開発できます。

```bash
# 依存関係のインストール
npm install

# 開発サーバーを起動（Expo）
npm start
```

起動後、Expo Go アプリまたは開発ビルドで実機・エミュレータに読み込みます。

### よく使うコマンド

```bash
npm run android     # Android で起動
npm run ios         # iOS で起動
npm run web         # Web で起動
npm run typecheck   # 型チェック（tsc --noEmit）
npm test            # ユニットテスト（Jest）
```

## ビルドと提出（EAS）

Google Play 向けの AAB ビルドとストア提出は EAS で行います（ローカルOSを問わずクラウドでビルド）。

```bash
# AAB ビルド（Google Play 必須形式）
eas build --platform android --profile production

# ストアへ提出（クローズドテスト: eas.json の track=internal）
eas submit --platform android --profile production
```

- 一般公開時は `eas.json` の `track` を `production` に変更します。
- `google-services-key.json`（サービスアカウントキー）は秘密情報のため **コミットしません**（`.gitignore` 済み）。

## プロジェクト構成

```
app/        expo-router の画面（ホーム・曲詳細・登録/編集・設定・ヘルプ ほか）
src/
  db/         SQLite 接続・スキーマ・マイグレーション・CRUD
  features/   曲検索モーダル（songSearch）
  hooks/      データ取得フック
  components/  UI コンポーネント
  lib/        機種ロジック・バックアップ・かな正規化・日付ユーティリティ
  constants/  デザイントークン・定数
  data/       ヘルプ文言
docs/       仕様書・リリース手順・ワイヤーフレーム
```

データモデル・設計方針・実装仕様の詳細は [`CLAUDE.md`](./CLAUDE.md) を参照してください。

## データとプライバシー

- アプリで扱うデータ（曲・点数・タブ・設定など）は **すべて端末内に保存** されます。
- 外部送信は **曲検索時の iTunes Search API への検索キーワードのみ**。個人を特定する情報は収集しません。
- 詳細は [プライバシーポリシー](./privacy-policy.html) / [利用規約](./terms-of-use.html) を参照してください。
