# 1.1.0 仕様書：曲の追加・編集フロー再設計

> versionName：1.1.0 / ターゲットAPI：36 / 前提：1.0.1（`SearchResultList`）と 1.0.2（API 36）が完了していること
> 索引：[README.md](./README.md) / 画面：`docs/wireframe/歌帳 ワイヤーフレーム v6.html` のセクション C

## 1. 背景

現在の曲登録画面（04）は、曲名入力欄の下に iTunes の候補がインライン表示される形式で、検索と入力が1画面に詰め込まれている。候補が見切れる不具合（fix-F）の根本原因もこの構造にある。また、候補が少ないときに「表示が打ち切られているのか、該当曲がないのか」をユーザーが判断できない。

そこで、**検索を独立した画面（モーダル）に分離**し、カラオケの選曲端末に近い操作感で「曲から／アーティストから／キーワード」を切り替えて探せるようにする。フォームは検索で選んだ結果を受け取るだけの役割にする。

iTunes Search API は1回の取得が最大200件で、総ヒット数を返さない。そのため「すべて表示」は不可能であり、代わりに**取得結果の状態（全件か、打ち切りか、0件か、通信エラーか）をユーザーに明示する**ことで判断できるようにする。

## 2. スコープ

### やること
- 曲検索モーダル（選択画面 04a ＋ 検索画面 04b）の新設
- 曲登録フォーム（04）からインライン候補を削除し、テキスト欄に変更
- 編集フォームに「曲を変更」ボタンを追加
- 重複登録チェックを編集時の保存にも適用
- ヘルプ画面の「曲の追加方法」の文言更新

### やらないこと
- DB スキーマの変更
- 持ち歌リスト（01）の検索・並び替えの変更（追加メモの「ひらがな・カタカナ対応」「あいうえお順」は別件）
- 点数記録・グラフ・設定など他の画面の変更

## 3. 用語

| 用語 | 意味 |
|---|---|
| 検索モーダル | 04a と 04b をまとめた、画面の上に重なって表示される部品 `SongSearchModal` |
| モード | 検索対象の種類。「曲から」「アーティスト」「キーワード」の3つ |
| 候補 | iTunes から取得した曲1件（`SongCandidate`） |
| 取得上限 | 1回の検索で iTunes から取る最大件数。200件 |
| 表示単位 | 一度に画面に出す件数。50件 |

## 4. 画面とフロー

画面IDは画面設計（Notion）・ワイヤーフレーム v6 と共通。

### 4.1 新規追加
```
01 持ち歌リスト
 └─「＋」→ 04a 選択画面（手入力あり）
      ├─ 曲から探す／アーティストから探す／キーワードで探す
      │    → 04b 検索画面（選んだモードで開く）
      │         ├─ 候補をタップ → モーダルを閉じる → 04 登録フォーム（曲名・アーティスト・アート入力済み）
      │         └─「手入力で登録」 → モーダルを閉じる → 04 登録フォーム（空）
      └─ 手入力で登録 → モーダルを閉じる → 04 登録フォーム（空）
```

### 4.2 編集
```
01b 左スワイプ「編集」→ 04 編集フォーム
 └─「曲を変更」→ 04a 選択画面（手入力なし）
      → 04b 検索画面（現在の曲情報を入力済み・自動検索済み）
           → 候補をタップ → 確認ダイアログ
                ├─「変更する」→ モーダルを閉じる → 04 編集フォームに反映（まだ保存しない）
                └─「戻る」→ 04b に留まる
 └─「保存する」→ 重複チェック → DB に保存
```

## 5. 詳細仕様

### 5.1 04a 選択画面
- ボタンは上から「曲から探す」「アーティストから探す」「キーワードで探す」「手入力で登録」
- 「手入力で登録」は新規追加時のみ表示する（編集フォームの曲名・アーティスト名はテキスト欄なので、入口を1つにするため）
- 押したボタンのモードが、04b の初期モードになる
- ヘッダー：新規追加時は「曲を追加」、曲変更時は「曲を変更」。左上の ✕ でモーダルを閉じる

### 5.2 04b 検索画面
- 上から順に：ヘッダー（‹ で 04a に戻る）→ 検索欄 → モード切り替え → 件数・並び替え → 結果リスト → 手入力の導線
- **検索欄**：入力があるときは右端に一括クリアボタン（ⓧ）を表示し、タップで入力を空にする。空にしたら結果も消す
- **モード切り替え**：「曲から」「アーティスト」「キーワード」の3つのボタン。いつでも切り替えられる。**切り替えたら、入力済みの文字のまま自動で再検索する**
- **検索の実行**：入力が止まってから一定時間後に自動で検索する（デバウンス）。待ち時間は ⚠️ A1 の調査結果の現行値を使う。現行に無い場合は 300ms とする
- **手入力の導線**：結果リストの下に「見つからない場合は手入力で登録」を表示する（新規追加時のみ）

### 5.3 iTunes API へのリクエスト

| パラメータ | 値 | 備考 |
|---|---|---|
| term | 検索欄の文字（前後の空白を除去） | 空なら検索しない |
| media | `music` | |
| entity | `song` | |
| attribute | 曲から＝`songTerm` ／ アーティスト＝`artistTerm` ／ キーワード＝指定しない | モードで検索対象を絞る |
| country | ⚠️ A1 の調査結果の現行値を維持（`JP` を想定） | |
| lang | ⚠️ A1 の調査結果の現行値を維持 | |
| limit | `200` | 取得上限 |

- iTunes Search API は1分あたり約20回の呼び出し制限がある。デバウンスで無駄な呼び出しを防ぐ
- 通信失敗（ネットワークエラー、HTTP エラー、JSON の解析失敗）と「0件」は必ず区別する

### 5.4 結果の表示状態（4状態）

| 状態 | 条件 | 件数欄の表示 | 本文 |
|---|---|---|---|
| 0件 | 取得成功・0件 | 表示しない | 「見つかりませんでした」＋「アーティストやキーワードでも探してみてください」＋手入力ボタン（新規時） |
| 全件 | 取得成功・1〜199件 | 「N件」 | 結果リスト |
| 上限到達 | 取得成功・200件ちょうど | 「上位200件」 | 「結果が多いため上位200件を表示しています。キーワードを足すと絞り込めます」＋結果リスト |
| 通信エラー | 取得失敗 | 表示しない | 「通信できませんでした」＋「電波の良い場所で再試行するか、手入力で登録してください」＋「再試行」ボタン＋手入力ボタン（新規時） |

- 検索前（入力が空）は何も表示しない
- 検索中は結果欄に読み込み中の表示を出す

### 5.5 ページング（表示単位）
- 最初は50件だけ表示する
- 残りがある場合、リストの最後に「もっと見る（51〜100件）」ボタンを出す。押すと次の50件を追加表示する
- すべて表示したらボタンを出さない
- 取得は最初の1回（最大200件）だけ。「もっと見る」では通信しない

### 5.6 並び替え
- 件数欄の右に並び替えボタン（現在の並び順を表示）。タップでメニューを開く
- 並び順は4種類：

| 並び順 | ルール |
|---|---|
| 関連度順（既定） | iTunes が返した順番のまま |
| 発売日が新しい順 | `releaseDate` の降順。日付が無いものは最後 |
| 発売日が古い順 | `releaseDate` の昇順。日付が無いものは最後 |
| 曲名順 | 曲名を `Intl.Collator('ja')` で比較。⚠️ B3 で Hermes での動作を確認し、期待どおりでなければ「カタカナをひらがなに変換して比較」に切り替える |

- 並び順を変えたら、表示件数を最初の50件に戻し、リストの一番上までスクロールする
- 並び替えは取得済みの候補全体（最大200件）に対して行う
- 同じ値のものは元の順番（関連度順）を保つ（安定ソート）
- 補足：iTunes には読み仮名のデータがないため、曲名順は漢字の曲名で完全なあいうえお順にならない。ひらがな・カタカナの曲名は正しく並ぶ

### 5.7 リセット規則
- モーダルを開くたびに、検索欄・結果・並び順（関連度順）・表示件数（50件）をすべて初期状態に戻す
- モードは 04a で選んだものにする

### 5.8 04 登録フォーム（新規追加）
- 曲名・アーティスト名は**サジェストなしの普通のテキスト欄**。検索から来た場合も入力済みの状態で編集できる（iTunes の表記を自分好みに直せる）
- アルバムアートは検索で選んだ候補のものを表示する。手入力の場合はプレースホルダー（🎵）
- キー・タブ・メモは現行どおり
- 「曲を追加する」押下時に、現行どおり重複登録チェックを行う

### 5.9 04 編集フォーム
- 曲名・アーティスト名は**サジェストなしのテキスト欄**
- アルバムアートの横に「曲を変更」ボタンを置く
- 曲名を手で書き換えても、アルバムアートは元のまま残す
- 「曲を変更」の流れ：
  1. 04a（手入力なし）を開く
  2. 選んだモードに合わせて、現在の曲情報を検索欄に入れて自動検索する
     - 曲から＝曲名 ／ アーティスト＝アーティスト名 ／ キーワード＝曲名＋半角スペース＋アーティスト名
  3. 候補をタップすると確認ダイアログ（OS 標準の `Alert`）を出す
     - タイトル：「曲を変更しますか？」
     - 本文：「〇〇（△△）」に置き換えます。キー・メモ・タブ・点数はそのまま引き継がれ、「保存する」で確定します。別の曲として記録する場合は、新しく追加してください。
     - ボタン：［戻る］［変更する］
  4. 「変更する」で、フォームの曲名・アーティスト名・アルバムアートを置き換えてモーダルを閉じる。**この時点では DB に保存しない**
  5. 「保存する」で DB に保存する。途中でフォームを閉じれば何も変わらない
- キー・メモ・タブ・点数履歴は常にすべて引き継ぐ（「曲を変更」は登録ミスの修正専用。別の曲にしたい場合は新規追加）

### 5.10 重複登録チェック
- 判定基準・ダイアログ文言は現行どおり（曲名＋アーティスト名、前後の空白除去・大文字小文字を無視）
- 新規：「曲を追加する」押下時（現行どおり）
- **編集：「保存する」押下時にも実行する。比較対象から編集中の曲自身を除外する**（除外しないと、何も変えずに保存しただけで警告が出る）
- ダイアログは OS 標準の `Alert` を使う（モーダルの上に別のモーダルを重ねると iOS で表示されないことがあるため）

### 5.11 戻る操作
- 04b で戻る操作 → 04a に戻る
- 04a で戻る操作 → モーダルを閉じる
- API 36 の予測型戻る方式で上記が成り立つことを実機で確認する

## 6. 設計

⚠️ ファイル配置は既存のディレクトリ構成に合わせて調整してよい。責務の分け方は守ること。

### 6.1 ファイル構成（案）
```
src/features/songSearch/
  types.ts           型定義
  constants.ts       定数（取得上限・表示単位など）
  itunes.ts          iTunes API の呼び出し（通信だけを担当）
  logic.ts           純粋関数（表示状態・並び替え・切り出し・初期入力）
  useSongSearch.ts   状態管理のフック
  SongSearchModal.tsx  モーダル本体（04a・04b）
  SearchResultList.tsx 1.0.1 で作成済みの部品を移動または参照
```

### 6.2 型と定数
```ts
export type SearchMode = 'song' | 'artist' | 'keyword';
export type SortKey = 'relevance' | 'releaseDesc' | 'releaseAsc' | 'title';
export type SearchStatus = 'idle' | 'loading' | 'empty' | 'complete' | 'truncated' | 'error';

export type SongCandidate = {
  trackId: number;
  title: string;
  artist: string;
  artworkUrl: string | null;
  releaseDate: string | null; // ISO 8601
};

export const FETCH_LIMIT = 200;
export const PAGE_SIZE = 50;
```

### 6.3 iTunes 呼び出し
```ts
type SearchResult =
  | { ok: true; items: SongCandidate[] }
  | { ok: false; reason: 'network' | 'http' | 'parse' };

export async function searchSongs(term: string, mode: SearchMode): Promise<SearchResult>;
```
- 例外を投げずに結果の型で成功・失敗を返す（呼び出し側で「0件」と「失敗」を確実に区別するため）

### 6.4 純粋関数（logic.ts）
入力が同じなら必ず同じ結果を返し、画面や通信に依存しない関数。単体テストの対象。
```ts
export function getSearchStatus(result: SearchResult | null, isLoading: boolean): SearchStatus;
// null（未検索）→ idle、読み込み中 → loading、失敗 → error、
// 0件 → empty、FETCH_LIMIT 未満 → complete、FETCH_LIMIT ちょうど → truncated

export function sortCandidates(items: SongCandidate[], key: SortKey): SongCandidate[];
// 元の配列を変更せず新しい配列を返す。安定ソート

export function paginate(items: SongCandidate[], visibleCount: number): SongCandidate[];

export function buildInitialQuery(mode: SearchMode, title: string, artist: string): string;
```

### 6.5 フック（useSongSearch.ts）
- 持つ状態：`query`、`mode`、`result`、`isLoading`、`sortKey`、`visibleCount`
- `query` または `mode` が変わったらデバウンス後に検索する
- 古い検索の結果が後から届いても、最新の検索結果を上書きしない（入力中の連続検索で表示が戻る事故を防ぐ）
- `reset(initialMode, initialQuery?)` で 5.7 のリセットを行う

### 6.6 モーダル（SongSearchModal.tsx）
```ts
type SongSearchModalProps = {
  visible: boolean;
  purpose: 'add' | 'change';          // 'add'＝手入力あり、'change'＝手入力なし
  currentSong?: { title: string; artist: string }; // 'change' のときの初期入力用
  onSelect: (candidate: SongCandidate) => void;
  onManual?: () => void;               // 'add' のときのみ
  onClose: () => void;
};
```
- 04a と 04b の切り替えはモーダル内部の状態で持つ
- **新規追加時は「モーダルを閉じる → 閉じ終わってからフォームへ遷移」の順にする**。同時に行うとモーダルが残ったり画面がちらついたりすることがある
- 「曲を変更」の確認ダイアログは `onSelect` を受けたフォーム側で出す（モーダルは確認の有無を知らない）
